## 5. 已记录但未修的真实缺陷

### 5.1 `hiddenRoundIds` 没有持久化，也没有 unhide 控件（**破坏性**）

> **2026-09-08 已修复**（本 PR 的 feature commit）：按会话独立键
> `edge-ai-sidebar:hidden-rounds:{sid}` 持久化（彻底解决 `boot-<n>` 跨会话撞号）；
> 列表底部"N hidden rounds — click to show"条进入恢复模式，隐藏轮原位变暗、
> ✕ 变 ↩ 可恢复；同会话多标签页经 `chrome.storage.onChanged` 同步。
> 顺带修复了 `renderKey` 不含隐藏状态导致 ✕ 点击被快速路径吞掉的存量 bug。
> 以下为修复前的原始记录：

轮次的 ✕ 隐藏按钮把 id 加进一个 `Set`，只在会话切换时由 `resetHiddenRounds()` 清空。
刷新页面后隐藏状态丢失；而且**没有任何 UI 能把某一轮重新显示出来**。

更糟的是轮次 id 不是会话隔离的（`boot-<n>` 是确定性的，`round.id = msg.id`），
所以隐藏某一轮会影响后续会话里编号相同的那一轮。

**要修就必须同时提供 unhide 控件**，否则 ✕ 是不可逆操作。这是新功能，不是补测试。

### 5.2 `renderUI` 快速路径下 `data-ai-sidebar-mode` 会停在旧值（已按现状钉住）

`syncHostAttributes` 在快速路径 `return` **之后**才调用，而该属性取自
`location.pathname`，**不在 `renderKey` 里**。所以路由单独变化不会让快速路径失效，
属性停在旧值。

实践中影响面很窄：路由变化会经 `handleRouteChange` 清空 store、轮次 id 随之改变，
从而触发真实渲染。

**这是有意保留的**，`tests/unit/render.test.ts` 里有用例 `leaves host attributes stale
on the fast path` 把它钉住并写明理由：修它意味着每次 debounce 的 observer tick 上做
4 次 `setAttribute`，正是快速路径要省掉的开销。若要改，先改这个用例。

无法针对真实的 arena.ai DOM 验证，只做了可验证的那一半。不要"顺手改进"。

## 6. 测试基建的既有约定（踩过的坑，别重复踩）

### 模块级状态 + 长生命周期监听器

挂在 `document` / `document.body` 上的监听器**不会被 `document.body.innerHTML = ""`
清掉**，且 `vi.resetModules()` 给下一个测试的新模块实例里 `observer` 变量是 `null`，
它自己的 `disconnect()` 清不掉上一个测试泄漏的。

**每个 `Disposer` 都要在 `afterEach` 里释放。** 见 `loop.test.ts`、`keyboard.test.ts`、
`fab.test.ts` 的 `disposers` 登记表模式。

### `vi.clearAllMocks()` 不清实现

它只清调用记录。某个用例里设的 `mockImplementation` 会泄漏到后续用例。
需要区分：

- `mockReset()` + 重装默认实现（`render.test.ts` 的 `resetHooks()`）
- `mockClear()` 只清记录（`render.test.ts` 的 `clearCalls()`）

### vitest 5 的 mock 类型

`ReturnType<typeof vi.fn>` 解析成 `Mock<Constructable | Procedure>`，**不可赋值给
`() => void`**。声明成 `Mock<() => void>`（`import { type Mock } from "vitest"`）。

### jsdom 缺失、必须打桩的 API

| API | jsdom 行为 |
|---|---|
| `scrollIntoView` | **不存在**，调用直接抛 `TypeError` |
| `isContentEditable` | 未实现，即使 `contentEditable="true"` 仍是 `undefined` |
| `getBoundingClientRect` | 返回全零，位移计算恒为 0 |
| `URL.createObjectURL` / `revokeObjectURL` | **不存在** |
| `requestAnimationFrame` | **不存在** |
| `window.prompt` | 打日志返回 `undefined` |
| `navigator.clipboard` | 不存在（用 `setClipboardBackend`） |

可用的：`MutationObserver`、`attachShadow`、`DOMParser`、`history.pushState`、
`window.open`、`Blob`、`HTMLTextAreaElement.prototype.value` 的 setter。

### 会话关闭后 token 会被换成占位符

会话因 PR 合并而关闭后，沙箱里的 `GH_TOKEN` / `GITHUB_TOKEN` **不是过期的真 token，
而是 24 字符、以 `aren` 开头的占位符**，既不匹配任何 GitHub token 前缀
（`ghp_` / `gho_` / `ghu_` / `ghs_` / `ghr_` / `github_pat_`），
也不满足 HTTP header 的字符集要求（含非 `[A-Za-z0-9_]` 字符）。

所以"重试一次说不定就好了"是没有意义的——它不会因为重试而变成有效凭据。
不必反复尝试推送，直接开新会话。判断方法（不打印 token 本身）：

```bash
python3 -c "import os;v=os.environ['GH_TOKEN'];print(len(v), v[:4])"
# 24 aren  →  占位符，远端操作必然失败
```

## 7. 已确立的契约（`tests/unit/` 是权威）

- **Storage**：`storageGet → unknown`、`storageSet/Remove → boolean`、
  `storageAvailable()`、`onStorageChanged(key, cb) → Disposer`、
  `setStorageBackend(fake|null)`。**永不 reject。**
- **Clipboard**：`copyText(text) → Promise<boolean>`、`setClipboardBackend(fake|null)`。
  **永不 reject；一次失败不得污染下一次调用。** 注意 `ClipboardBackend.writeText`
  返回 `Promise<void>`，`copyText` 才把它转成 boolean。
- **`beginInlineRename({target, initial, onCommit, onCancel?})`**：Enter 或 blur 提交
  **trim 后**的值，Escape 取消，**清空字段也算取消**；至多 settle 一次。
- **`renderKey`**：`({isOpen, searchQuery, reverseOrder, roundIds}) →
  JSON.stringify([...])` —— 裸 `join()` 会让含分隔符的 id 相撞。
- **`routeKey(pathname, search)`**：会话页返回 `"c:"+sid`（所以 query 变化不算导航），
  否则 `pathname+search`。`getSessionId` 用锚定的 `/^\/c\/([^\/?#]+)/`。
- **`resolveSessionTitle(meta)`**：`customTitle.trim()` → `title.trim()` →
  `sessionId.slice(0,8)`。**永不返回 `""`。**
- **`setSessionCustomTitle(sessionId, customTitle)`**：`titleCache` 删除后唯一的改名
  写入路径，末尾调 `saveToStorage()`。
